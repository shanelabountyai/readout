# Implementation plan

How N3 Weekly Business Pulse gets from this PRD to a demo. The PRD (`docs/prd-readout.md`) says what; `docs/DECISIONS.md` records every call and outranks the PRD; this file says in what order and how we know each phase is done. Phase 1 has its own detailed plan (`docs/PHASE-1-PLAN.md`); Phases 2 and 3 get theirs at the previous phase's gate.

## Principles

- **Mirror N7** (`shanelabountyai/meeting-follow-up`): logic in `src/` as pure CommonJS run inside n8n Code nodes; `workflow.json` generated by a build script and never hand-edited; `npm run gate` = lint + drift check + tests; tests never call a model or a live API.
- **Fixtures first.** The 20 golden weeks of PRD §9 are written before the code that must reproduce them. Expected values are copied from the PRD, never generated by the engine.
- **Code computes, the model writes, code checks.** Nothing the model says reaches the page unchecked.
- **Phase gate.** No work on phase N+1 while phase N's exit criteria fail. Each phase ends with a PR, `NEXT.md` updated, and the next phase's plan written and left for review.
- **Ask-before-add.** No runtime dependencies. Adding any devDependency beyond N7's four (`ajv`, `eslint`, `@eslint/js`, `globals`), any date library, any CSV parser or any HTTP client needs a D-row and should be avoided.

## Phases

### Phase 1 — pure engine, checks, fixtures, workflow skeleton (offline)

Scope, module list, tests and exit criteria: `docs/PHASE-1-PLAN.md`. Branch `phase-1`, one PR to `main`.

### Phase 2 — n8n wiring and simulated run (offline)

- Fill in every external node: HubSpot GET list calls with paging (`after`), `propertiesWithHistory=dealstage`, page cap; Sheets `values.get` for `weekly`, `definitions` and the ledger; Anthropic Messages via HTTP Request with the forced tool; Drive multipart upload with conversion to a Google Doc and `files.update` for re-runs; Gmail node Create draft and HTTP `PUT drafts/{id}` for updates; Sheets append for the ledger; Error Trigger to an `errors` row and an optional throttled webhook.
- Retries: every read 3 tries; Create draft no auto-retry (N7 D-33).
- `test/n8n-sim.js`: execute `workflow.json` itself against in-memory fakes of HubSpot, Sheets, Drive, Gmail and the model (recorded stand-ins) for all 20 golden weeks; assert the PRD §9 outcome and the request log (no non-GET to HubSpot, no send path).
- `docs/SETUP.md`: import, the four credentials and their minimum scopes (D-021), the Drive folder and the two sheets with their headers, config fields.
- Exit: simulated run reproduces every §9 outcome; AC-02, AC-10, AC-15 pass; gate green in CI.

### Phase 3 — demo, eval, closeout

- Seed data for the demo HubSpot portal (`[demo]` deals with stage history, `.example` contacts, `[demo]` tasks) and a seed sheet, matching E01's baseline so the live page can be compared with the expected one.
- `docs/DEMO.md` (about 5 minutes): empty Pulse folder → manual run → the Doc → the draft in Gmail → E09-style narrative rejection shown as "Narrative withheld" → re-run updates in place.
- `docs/EVAL.md`: offline results (recorded stand-ins, not model accuracy) and a section for Shane's live run; runtime and cost labelled "target, not measured" until measured.
- `docs/ACCEPTANCE.md`: every AC with offline and live evidence; live items "not run" until Shane runs them.
- README status line; closeout notes in `NEXT.md`.
- Shane's hand steps (never done by a cloud run): import into his n8n, create the credentials, seed the portal and sheet, one manual run, Gmail audit.

## Risks and how the plan handles them

| Risk | Handling |
|---|---|
| HubSpot `propertiesWithHistory` limits page size, or tasks need a scope we did not list | Phase 2 checks the documented limits and records a D-row; the page cap (D-025) bounds the damage; "Not verified" lists it until a live run. |
| `Intl` time-zone data missing in the n8n Node build | `week.js` tests run in CI on stock Node 22 (full ICU); SETUP notes the requirement; a Phase 2 fallback is a fixed-offset table, added only with a D-row. |
| Model narrative fails checks often, so most pages are metrics-only | That is a safe failure; Phase 3 live eval counts it; prompt changes bump `narrate-vX.Y`. |
| Drive HTML-to-Doc conversion renders tables poorly | Phase 2 keeps HTML simple (one table, headings, paragraphs); a plain-text fallback is a D-row away. |
| Fixture arithmetic wrong in the PRD | Stop and show both derivations (PHASE-1-PLAN); fix by D-row and PRD edit. |
