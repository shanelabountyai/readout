# Phase 1 plan — pure engine, checks, fixtures, workflow skeleton (offline)

Read first: `docs/prd-readout.md` (what), `docs/DECISIONS.md` (outranks the PRD where they differ), `CLAUDE.md` (rules). This plan is self-contained: a fresh session can build Phase 1 from it without asking anything. Where it is silent, take the most reasonable reading, record it as the next D-row, and keep going.

**No model, no live API.** Every test runs offline. Nothing in Phase 1 calls HubSpot, Google or Anthropic. The only network use is `npm install` from the npm registry (normally reachable from a cloud session; if it is not, write the files, record in `NEXT.md` that the gate is CI-only, and let CI decide). Everything the build needs from sibling repos is written out in this plan, so no other repo has to be read; reading N7 (`shanelabountyai/meeting-follow-up` at `59d0374`, public) is optional, for style.

**Merging.** Readout PRs may be merged under Shane's rule (D-003) only when every condition holds, including a review by a fresh agent that saw only the diff and the plans and left no unfixed MUST-FIX. If you cannot run such a review, open the PR and stop; do not merge.

## Exit criteria

1. `npm ci && npm run gate` passes locally (lint, `check` drift, tests) on Node 22, or, if the npm registry is unreachable from the session, this is recorded in `NEXT.md` as CI-only.
2. GitHub Actions `gate` workflow passes on the PR (D-030).
3. Each of the 20 golden weeks in PRD §9 is a fixture and a passing test with the exact expected metrics, renderings, flags, check result and outcome. The five extra check variants (AC-07) pass.
4. AC-01, AC-03 to AC-09, AC-11 to AC-14 and AC-16 have a named test.
5. `workflow.json` is generated by `npm run build`, is inactive, and `npm run check` fails if it is stale.
6. `NEXT.md` updated: what was built, the gate output (test count), what is left for Phase 2. New D-rows for every call made.

Then stop: write `docs/PHASE-2-PLAN.md` and leave it for review. Do not start Phase 2 wiring.

## Modules (`src/`)

Pure functions; inputs are plain JSON; time is passed in as an ISO UTC string; no `require` of anything but other `src/` modules and Node builtins allowed in n8n Code nodes (`crypto` is not needed in Phase 1).

### `src/num.js` — integer arithmetic and renderings

- **Inputs:** integers (cents or counts), rationals as `{ num, den }` with `den` any positive integer (4 for averages; `prev` or `sum4` for percentages; ×100 for cents to dollars).
- **Outputs:** `roundHalfAway(num, den) → integer`; `parseDollars(str) → { ok, cents } | { ok: false }`; `renderCount(n)`, `renderCountAvg(sum4)` (one decimal), `renderCountDelta`, `renderMoney(cents)`, `renderMoneyDelta`, `renderPct(num, den)` (whole percent with sign), and `magnitudeOf(rendering) → { type, value }` used by the checks.
- **Invariants:** no float arithmetic on money; `roundHalfAway(5, 2) = 3`, `roundHalfAway(-5, 2) = -3`, `roundHalfAway(100, 3) = 33`, `roundHalfAway(-100, 2) = -50`, `roundHalfAway(1950, 4) = 488` (cents 487.5 → 488); the minus sign in renderings is U+2212 `−`, and the parser accepts `-` and `−`. `parseDollars` accepts a leading minus (negative cash is allowed; `cash_drop` needs `prev > 0`); `($5,000)` accounting style is rejected as `sheet_invalid`.
- **Tests (`test/num.test.js`):** half-away cases incl. negatives and exact halves (12.5 → 13, −12.5 → −13, 8.25 → 8.3 at one decimal, 0.75 → 0.8, 0.42 → 0); `parseDollars` accepts `46000`, `46,000`, `46000.50`, `$46,000`, accepts `-5,000`; rejects `46k`, `4.5m`, `46,00`, `1.234`, `($5,000)`, empty; renderings `$46,000`, `+$4,000`, `−$14,000`, `$0`, `+33%`, `0%`, `3.0`, `+0.8`.

### `src/week.js` — report week and the five-week window

- **Inputs:** `runAtIso` (UTC), `timezone`, `weekStartOverride` (`''` or `YYYY-MM-DD`, must be a Monday).
- **Outputs:** `{ weekStart: 'YYYY-MM-DD', startUtc, endUtc, window: [ {weekStart, startUtc, endUtc} × 5 ] }`, oldest first, last = report week; `calendarWeekOf(runAtIso, tz)` for the spend cap.
- **Invariants:** Monday 00:00 local boundaries via `Intl.DateTimeFormat` with `timeZone` (no date library: none may be added without asking); half-open; a run exactly at Monday 00:00 local reports the week that just ended.
- **Tests (`test/week.test.js`):** runs `2026-11-23T16:00:00Z` (the Monday 10:00 schedule) and `2026-11-23T13:00:00Z` → `2026-11-16`, start `2026-11-16T06:00:00Z`, end `2026-11-23T06:00:00Z`; week `2026-10-26` is 169 hours (DST ends 2026-11-01); week `2027-03-08` is 167 hours (DST starts 2027-03-14); `calendarWeekOf('2026-11-23T16:00:00Z')` starts `2026-11-23T06:00:00Z`; override not a Monday → error; run at `2026-11-23T06:00:00Z` (Mon 00:00 CST) → `2026-11-16`.

### `src/hubspot.js` — normalise raw HubSpot pages; demo guard

- **Inputs:** arrays of raw HubSpot objects as returned by `GET /crm/v3/objects/{deals|contacts|tasks}` with explicit `properties=` (deals: `dealname, dealstage, pipeline, amount, createdate, closedate, notes_last_updated` and `propertiesWithHistory=dealstage`; contacts: `email, createdate`; tasks: `hs_task_subject, hs_task_status, hs_timestamp`), `cfg`, and `truncated` booleans per object.
- **Outputs:** `{ deals: [{id, name, stage, amountCents|null, createdAt, closedAt|null, lastActivityAt, stageHistory: [{value, at}] oldest first}], contacts: [{id, createdAt}], tasks: [{id, status, dueAt|null}], skipped: { deals, contacts, tasks }, truncated: {...} }`. Contact emails and names and task subjects are dropped after the guard (D-032).
- **Invariants:** deals outside `cfg.pipelineId` are dropped (not counted as skipped); demo guard per D-016 (`[demo]` prefix on `dealname` / `hs_task_subject`; contact `email` domain ends `.example`; a contact with no email is excluded and counted as skipped); amounts parsed with `num.parseDollars` (HubSpot returns strings); unparseable amount → `null` (counted in Data notes, D-023).
- **Tests (`test/hubspot.test.js`):** guard excludes a `.test` contact and a deal without the prefix and counts them; history sorted; missing `notes_last_updated` falls back to `createdate`; a `"18000.00"` amount → 1,800,000 cents.

### `src/metrics.js` — weekly metrics

- **Inputs:** normalised records, `window`, `cfg` (stage lists), `rules/stale.json` contents, `runAtIso`.
- **Outputs:** `{ series: { deals_created: [5], deals_moved: [5], deals_won: [5], won_amount: [5], deals_lost: [5], new_contacts: [5] }, snapshot: { open_pipeline, stalled: [{name, stage, idleDays}] (idle desc, then name), overdue_tasks }, notes: { wonMissingAmount: <count>, openMissingAmount: <count>, unknownStages: [stage ids] } }` (counts, never names, D-032).
- **Invariants:** PRD §4 and D-015, D-022, D-023, D-033, D-041 exactly; `[start, end)`; a history entry equal to the one before it is not a move; stalled uses the report week's end; last activity = max(`notes_last_updated`, latest `dealstage` history timestamp), else `createdate`; idle days = `floor((endUtc − lastActivity) / 86,400,000)` and stalled iff `idle > max_idle_days`; closed stages never stalled; overdue counts every `hs_task_status` except `COMPLETED`.
- **Tests (`test/metrics.test.js`):** E01 baseline series; a deal created and moved in the same week counts once in each; a move into `closedwon` is not a move; a repeated same-stage entry is not a move; a stage entry newer than `notes_last_updated` resets idle; a deal in another pipeline is ignored; E08 boundary (11 stalled, 21 not); overdue excludes completed and tasks due on/after week end.

### `src/sheet.js` — the weekly sheet

- **Inputs:** `values` of the `weekly` tab and of `definitions` (Sheets API `values` arrays read with `valueRenderOption=FORMATTED_VALUE`, header row first), `window`. `week_start` must read as the text `YYYY-MM-DD` (SETUP will say: format that column as plain text); money cells may read `46000`, `46,000.00` or `$46,000.00`.
- **Outputs:** `{ series: { revenue: [5 × cents|null], cash: [...], x_<key>: [...] }, defs: [{key,label,unit}], issues: [{code: 'sheet_missing'|'sheet_invalid', metric, weekStart}] }`. `sheet_missing` is raised **only for the report week**; a prior-week gap leaves a `null` in the series (which `compare.js` turns into `history_short`), never a `sheet_missing` issue.
- **Invariants:** rows keyed by `week_start`; a non-Monday or duplicate `week_start` is `sheet_invalid` for that row (first row wins); at most 5 extras, more are ignored with an issue; no free text passes through.
- **Tests (`test/sheet.test.js`):** E03 (missing row), E14 (two prior rows only: no `sheet_missing` issue), E19 (`46k`), duplicate week, a `count` extra, a date serial in `week_start` → `sheet_invalid`.

### `src/compare.js` — comparisons

- **Inputs:** a five-value series (oldest first) and a type (`count` | `money`).
- **Outputs:** `{ cur, prev, sum4, wow_abs, wow_pct, avg4, avg_abs, avg_pct }` with absent fields as `null`; rationals for `avg4`/`avg_abs` as `{num, den: 4}`; percentages as `{num, den}` before rendering.
- **Invariants:** PRD §4 formulas; `avg4` needs all four prior values; `wow_pct` null when `prev` is 0/null; `avg_pct` null when `sum4` is 0/null.
- **Tests (`test/compare.test.js`):** every comparison listed for E01, E02, E07, E09, E10, E14, E15 in PRD §9.

### `src/flags.js`

- **Inputs:** comparisons by metric, snapshot, sheet issues, hubspot skipped/truncated, `cfg.thresholds`.
- **Outputs:** ordered list `[{ code, metric?, sentence }]`; `sentence` is code-written from renderings.
- **Invariants:** PRD §5 rules with integer cross-multiplication; order: `quiet_week`, `stalled_deals`, `overdue_tasks`, `revenue_swing`, `cash_drop`, then data flags.
- **Tests (`test/flags.test.js`):** each flag fires on its golden week (`quiet_week` E02, `stalled_deals` E08, `overdue_tasks` E10, `revenue_swing` E09, `cash_drop` E10, `sheet_missing` E03, `sheet_invalid` E19, `history_short` E14, `demo_guard_skipped` E18, `hubspot_truncated` E01-truncated) and none fires on E01; `quiet_week` does not fire when `revenue_swing` or `cash_drop` does; `revenue_swing` exactly at 25% fires; cash rising never fires `cash_drop`.

### `src/facts.js` — the fact table

- **Inputs:** comparisons, snapshot, flags.
- **Outputs:** `[{ id, metric, field, label, type: 'count'|'money'|'pct', rendering, sign: -1|0|1, isDelta }]`, ids `<metric>.<field>` for fields `cur, prev, avg4, wow_abs, wow_pct, avg_abs, avg_pct` (`sum4` is never a fact), snapshot facts `open_pipeline.cur`, `stalled_deals.cur`, `overdue_tasks.cur`, and `stalled.<n>.idle_days`; absent values produce no fact. `sign` is the sign of the **exact** value (cash +$500 renders `0%` with sign +1).
- **Invariants:** renderings come only from `num.js`; the same table feeds the prompt, the checks and the Doc.
- **Tests (`test/facts.test.js`):** E01's 56 history facts and 3 snapshot facts match the PRD §9 E01 table exactly; E03 has no `revenue.cur`, `revenue.wow_*` or `revenue.avg_*` facts but keeps `revenue.prev` ($42,000) and `revenue.avg4` ($41,000); E15 has no `deals_won.wow_pct`.

### `src/prompt.js` — model request (built, never sent in tests)

- **Inputs:** facts, flags, stalled names, `prompts/narrate.md`, `prompts/narrate.schema.json`, `cfg`.
- **Outputs:** the Messages API request body with `tool_choice: { type: 'tool', name: 'write_pulse' }`, plus `estimatedInputTokens` (characters / 4).
- **Invariants:** no contact or task data in the body (test scans for `@` and `.example`); prompt version string in the output for the ledger.
- **Tests (`test/prompt.test.js`):** body shape; version `narrate-v0.1`; E01 body contains every fact id and no email address.

### `src/schema.js` — validate the tool input

- **Inputs:** tool input object.
- **Outputs:** `{ ok, errors }`.
- **Invariants:** hand-written validator, stricter than JSON Schema (extra keys fail); `test/schema.test.js` cross-checks it with Ajv against `prompts/narrate.schema.json` on all recorded stand-ins and variants (N7 pattern).

### `src/checks.js` — the narrative checks

- **Inputs:** validated narrative, facts, stalled names.
- **Outputs:** `{ pass, reason, failures: [{ reason, part, token? }] }`, `reason` = first failure by PRD §6 precedence.
- **Invariants:** PRD §6 exactly: phrase and ISO-date stripping, word and sentence definitions, the token regex, typed exact-decimal match, `direction_mismatch` on **any** contradicting cited fact, word lists as whole words, case-insensitive; `spelled_number` and `causal_claim` also scan suggestions. Word lists live in one exported constant each, so tests and docs can quote them.
- **Tests (`test/checks.test.js`):** each golden-week narrative (E01, E03–E15, E18, E19) gives its PRD result; one variant each for `schema`, `too_long`, `number_in_suggestion`, `spelled_number`, `unverifiable_claim`; precedence (a paragraph with both a missing cite and a stray number reports `cited_fact_missing`); explicit `+` on a negative fact fails `direction_mismatch`; "followed up" is a known false trigger, documented with a test that pins current behaviour.

### `src/template.js` — code-written narratives

- **Outputs:** quiet-week narrative (fixed headline "Quiet week in the CRM" with no digits, + one paragraph citing facts, never a direction word next to a zero rendering); the code-written headline "Weekly pulse: Mon 16 Nov – Sun 22 Nov 2026" used on every non-pass path; `REASON_WORDS`, a fixed map from each reason code to a plain-words line ("the draft quoted a number the data does not contain").
- **Tests:** the quiet-week template for E02 passes `checks.js`; every reason in the ledger's closed set has a `REASON_WORDS` entry. If a template ever fails its own check at run time the outcome is `metrics_only` with reason `template_check` (a test failure in CI).

### `src/doc.js` — the Google Doc HTML

- **Inputs:** week, facts, flags, narrative or withheld reason, suggestions, data notes, `cfg.firmName`.
- **Outputs:** an HTML string (headings, table) and the Doc title.
- **Invariants:** every model string HTML-escaped; no model string at all on a non-pass path; header with the week as a range; footer text exactly as PRD §7; table rows in PRD §4 order with the footnote "differences use the unrounded average"; snapshot rows labelled with when they were measured; absent values shown as "—" with a Data note; a Definitions block and the recompute caveat in Data notes.
- **Tests (`test/doc.test.js`):** E01 contains the table, footnote, Definitions and footer; a `<script>` in a narrative is escaped; E16 shows the code-written headline and `REASON_WORDS.weekly_cap`, and no text from any stand-in; E12 suggestion under its heading.

### `src/email.js` — the draft

- **Outputs:** `{ to, subject, body }` or `{ skip: 'demo_guard_recipient' }`.
- **Invariants:** `to` is `cfg.ownerEmail` only; demo-mode `.example` rule; body plain text, five code-built lines plus the Doc's headline (the model's only when the checks passed) and Doc link.
- **Tests (`test/email.test.js`):** subject format; non-`.example` owner in demo mode → skip; no model string other than the checked headline.

### `src/ledger.js` — runs rows

- **Columns:** `run_id, week_start, status, reason, flags, doc_id, draft_id, draft_state, prompt_version, model, model_calls, input_tokens, output_tokens, cost_usd, runtime_s, run_at`.
- **Codes:** `status ∈ {done, metrics_only, failed}`; `reason` from the closed set (the 11 check reasons, `template_check`, `weekly_cap`, `token_ceiling`, `spend_cap`, `hubspot_error`, `sheet_error`, `drive_error`, `gmail_error`, `model_error`, `demo_guard_recipient`, `''`); `flags` = flag codes joined by `|`; `draft_state ∈ {'', created, updated, gone, skipped}`.
- **Outputs:** `buildRow(fields) → array` (throws on anything else), `latestFor(records, weekStart) → { docId, draftId, draftState }` where each is taken from the **latest row with a non-empty value for that field** (a `failed` row with empty ids never hides an earlier Doc), `callsInCalendarWeek(records, calendarWeekStartUtc)`, `appendCall(...)` (Sheets API append, built not sent).
- **Tests (`test/ledger.test.js`):** refuses a dollar amount in `reason`, a name in `doc_id`, an unknown column; append-only; a `done` row then a `failed` row then a re-run → the same Doc id; `draft_state gone` is remembered.

### `src/spend.js`

- `precheck({ callsThisWeek, spentThisWeekUsd, cfg })` in `plan` (call and dollar caps) and `gate({ callsThisWeek, estimatedInputTokens, spentThisWeekUsd, cfg }) → { allowed, reason }` after the prompt is built (adds the token ceiling); `costUsd(usage, cfg)` (null while prices null), N7's shape.
- **Tests:** E16 (`weekly_cap`), token ceiling, dollar cap ignored while prices are null and enforced once set.

### `src/steps.js` — one function per Code node

`plan` (week, ledger lookup, spend precheck), `normalise` (hubspot + sheet), `compute` (metrics, compare, flags, facts, quiet decision, prompt, full spend gate), `review` (schema + checks, or template, or withheld), `render` (doc + email), `record` (ledger row), `errorRow` (an `errors` tab row with the failing node and a reason code; no business data). `test/harness.js` runs them in order against a golden week with recorded stand-ins and in-memory fakes and returns `{ outcome, reason, flags, facts, docHtml, draft, ledgerRow, errorRow, calls }`. The fakes support failure injection (`hubspotFailures` in the week file): for E20 the harness asserts no model call, no Doc, no draft, an `errors` row and status `failed`. Retries are Phase 2.

## Fixtures (Phase 1 writes them first, before the engine)

See `fixtures/README.md` for the format. `fixtures/spec.js` holds, per golden week, the compact inputs from PRD §9; Each week in `spec.js` also has an `expected` block **typed by hand from PRD §9** (metrics, fact renderings, flags, check result, outcome, model calls). `fixtures/build.js` expands the inputs into raw HubSpot-shaped pages (`fixtures/weeks/E01.json`: `deals`, `contacts`, `tasks`, `sheet`, `definitions`, `ledger`, `runAt`, `hubspotFailures`) and writes the `expected` block out unchanged as `fixtures/expected/E01.json`; it never runs the engine. `--check` compares both with the committed files. `fixtures/recorded/E01.json` holds the hand-written `write_pulse` tool input (and fake `usage` = characters/4, labelled as an estimate) for each non-quiet week, plus `variants/` for the five extra check reasons; `weeks/E01-truncated.json` (two pages of deals, `hubspotMaxPages` 1) is the input variant for `hubspot_truncated`; its expected block asserts only the flag, the Data notes line and that no model narrative check fails because of it. Stand-ins follow the PRD §9 convention (headline "The week in numbers" with no cites, one paragraph, empty suggestions unless the row says otherwise).

**If the engine disagrees with an expected file, stop and show both derivations in `NEXT.md`.** Never edit an expected value to make a test pass; the PRD table is the oracle, and a wrong PRD value is fixed by a dated D-row and a PRD edit, not silently.

## Workflow skeleton (`scripts/build-workflow.js`)

Generates `workflow.json` with `"active": false`, `settings.saveDataSuccessExecution: "none"`, and these nodes in order: `Schedule (Mon 10:00 America/Chicago)`, `Manual`, `config` (Set node from the template), Code `Plan`, HTTP `Read ledger`, HTTP `Read HubSpot deals/contacts/tasks` (GET, placeholders), HTTP `Read weekly sheet`, Code `Normalise`, Code `Compute`, IF `Model needed?`, HTTP `Anthropic` (placeholder), Code `Review`, Code `Render`, HTTP `Doc create/update`, Gmail `Create draft` / HTTP `Update draft`, HTTP `Append ledger`, Error Trigger → Code `Error row`. Code nodes inline `src/` (N7's bundle pattern: the build script concatenates each `src/` module into the Code node wrapped as `__load('<name>', function (module, exports, require) { <source> })`, where the injected `require` resolves `./x` to the already-loaded module, so the node runs exactly the tested code). External nodes carry placeholder parameters and a note `Phase 2`; credentials are placeholders named per D-021.
